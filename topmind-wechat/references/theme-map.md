# 题材 → 主题映射

「按题材分主题」的规约。主题文件在 `assets/themes/*.json`，
命令行 `--theme` 选主题，`--list-themes` 看全部，`genre:题材` 按题材自动选。

## 已注册主题

| 主题 | 标识 | 主色 | 标题样式 | 圆角 | 适用题材 |
|---|---|---|---|---|---|
| 极简黑白灰 | `minimal-ink` | `#A6524A` 砖红 | number | 4px | **默认**、观点、深度分析、随笔 |
| 科技蓝 | `tech-blue` | `#185FA5` 蓝 | number | 6px | 教程、实操、工具测评、建站 |
| 石墨灰阶 | `graphite` | `#52525B` 石墨 | underline | 0px | 技术说明、专业评论、方法、原理 |
| 报纸纸感 | `newsprint` | `#8C5A3C` 棕（衬线） | center | 0px | 复盘、特稿、行业观察、长文 |
| 琥珀评测 | `amber-review` | `#B45309` 琥珀 | number | 6px | 评测、模型评测、数据对比、榜单、速览 |

```bash
# 看清单
python3 scripts/md2wechat.py --list-themes

# 指定主题（三种写法都可以）
--theme amber-review        # 标识
--theme 琥珀评测            # 中文名
--theme genre:评测          # 按题材自动选
```

## 选题材的原则

**一句话**：主题跟着**题材**走，不跟着心情走。同一个题材永远用同一套主题，
读者才能形成视觉记忆。换题材时才换主题。

| 判断依据 | 走哪个主题 |
|---|---|
| 有大量数据对比、榜单、多维评分 | 琥珀评测 |
| 有步骤、命令、可复现的操作过程 | 科技蓝 |
| 讲原理、讲机制、专业观点输出，需要克制 | 石墨灰阶 |
| 讲一个完整案例的来龙去脉、时间跨度长 | 报纸纸感 |
| 观点表达、行业观察、随笔，没有明显题材特征 | 极简黑白灰（默认） |

**题材交叉时**（如"带步骤的模型评测"）：看**读者来干什么**。
来抄操作步骤的 → 科技蓝；来看结论和数据的 → 琥珀评测。

## 主题之间必须一致的东西

换主题**只换色彩与标题形态**，以下参数在所有主题间保持一致，不要随手改：

| 参数 | 统一值 | 理由 |
|---|---|---|
| 正文字号 | 16px | 公众号长文阅读舒适区 |
| 行高 | 1.75（报纸纸感 1.8） | 低于 1.7 会挤 |
| 段间距 | 22px（报纸纸感 24px） | 与行高成比例 |
| 对齐 | `left` | 中文 `justify` 会产生「河流」并触发格式告警 |
| 章节编号 | 全部由排版层生成 | 见 `element-spec.md`「章节编号」；末章收束类用 `∞` |
| 视觉层级规则 | 锚点层 ≤5 / 标记层每段 1–3 | 与主题无关，是阅读规律 |

**这些是阅读规律，不是审美偏好**，任何主题都不该改。

## 每套主题必须提供的字段

新增主题时字段缺一个，就会继承默认主题的值——**这正是历史 bug 的成因**：
`tech-blue` 当年只写了 14 个字段，`mark_bg` 落到默认主题的砖红浅底 `#FAF0EE`，
一套蓝色主题里冒出砖红高亮，于是从来没人敢用它。现在 `load_theme()` 会按各自主色
自动派生 `accent_light` / `accent_soft`，但**其余字段仍需显式写全**。

```jsonc
{
  "id": "标识（英文，命令行用）",
  "name": "中文名",
  "genre": ["题材1", "题材2"],        // `--theme genre:题材` 按此匹配，也用于 --list-themes 展示

  // 主色三件套：派生色可不写（自动按 accent 算），写了则以文件为准
  "accent": "#______",               // 唯一强调色
  "accent_light": "#______",         // 关键词下划线（标记层）
  "accent_soft": "#______",          // 高亮底 / 徽章底

  // 文字四级
  "text": "#______",                 // 正文
  "text_strong": "#______",          // 加粗、标题
  "text_muted": "#______",           // 斜体、脚注
  "text_light": "#______",           // 图注、数值说明、导读截断提示

  // 面与线
  "surface": "#______",              // 卡片底（stat/引用/签名/导读共用）
  "border": "#______",               // 表格线、金句上下框线
  "img_border": "#______",           // 图片描边

  // 代码块：色板按 accent 自动生成，配色方案二选一
  "code_bg": "#______",
  "code_text": "#______",
  "code_scheme": "mono",             // mono（推荐，只用主色+明暗）| palenight（不推荐）

  // 四种语义色（容器左边框）
  "c_note": "#______", "c_tip": "#______",
  "c_warn": "#______", "c_danger": "#______",

  // 形态
  "radius": "0px | 4px | 6px",       // 全主题统一圆角；直角最保守
  "h2_style": "number | bar | underline | center | plain",
  "line_height": "1.75",
  "para_gap": "22px",
  "align": "left",
  "font_size": "16px",

  // 结构组件
  "toc": true, "toc_max": 5, "toc_min_h2": 4, "toc_min_chars": 2000,
  "table_max_cols": 3,               // 超过就转卡片化

  "font_stack": "...", "mono_stack": "..."
}
```

## 加一套新主题的步骤

1. 在 `assets/themes/` 写 `{id}.json`，字段按上表写全
2. 跑 `python3 scripts/md2wechat.py --list-themes` 确认能被列出
3. 用一篇真实稿跑一遍，确认 `合规自检` 为 0 ERROR：
   `python3 scripts/md2wechat.py --input 稿.md --out-dir /tmp/t --slug t --theme {id}`
4. 在本文件的主题表里登记一行
5. 目视核对：**下划线色、高亮底、代码块关键字色是否都跟本主题主色同源**
   （不同源 = 又出现了色彩外溢）

## 主题与视觉层级的配合

三层标记手段在所有主题下的表现：

| 层 | 手段 | 主题相关性 |
|---|---|---|
| 锚点层 | 主色加粗 / 深色底白字引用 | 用 `text_strong`，**不用 accent**——浅色主题下 accent 加粗不够重 |
| 标记层 | 下划线 `accent_light` | 浅色主题用浅色调（砖红→`#E3BAB3`）；深色主题用主色本身（石墨→`#52525B`） |
| 容器层 | 底色 `surface` + 左边框 `accent` | 全主题统一结构，只换色 |

石墨灰阶的下划线特意用主色本身而不是浅色调：灰色主题里浅灰下划线几乎看不见，
起不到标记作用。**下划线色的选择标准是「能不能看见」，不是「够不够淡」。**

### `h2_style` 会连带影响导读

导读（前言看点）的标记跟随 `h2_style`：带编号的主题（`minimal-ink`/`tech-blue`/`amber-review`）
导读也编号，末章收束类同为 `∞`；不带编号的主题（`graphite` 下划线 / `newsprint` 上下框线）
导读只能用中性圆点。**换主题时导读会自动跟着变，不用手改**——但如果发现"导读有 01、正文没编号"，
那是渲染器 bug，不是主题配置问题。
