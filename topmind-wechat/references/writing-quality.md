# 写作质量参考

定稿前三关的可执行清单，以及这几轮改稿里真实踩过的坑。

## 一、事实关

### 检查动作

1. 列出全文所有承重数字（会被引用的、支撑结论的），逐条回溯一手来源
2. 一手来源优先级：厂商定价页/官方博客/官方公告 > arXiv 原文 > 政府与监管机构网站 > 标准组织官网 > 一手媒体报道
3. 标注口径：厂商自报标「厂商口径」；社区转述标「据报道」；预测类写清「这是预测，不是已发生的事实」
4. 无一手来源的传闻**直接删**，不要为了完整留着

### 高频错误

- **跨版本混用**：同一指标的不同年度版本数字混着用（IBM 2025 版 97% vs 2026 版 92%）
- **单位错误**：「人均代码 4450→7839 行」实际是每月不是每年
- **口径换算**：「3MB → 64MB 提高二十多倍」——前后计量方式不同（压缩后 MB vs 未压缩 MiB），不能换算
- **州别/主体错位**：「佛蒙特约 600 家数据经纪商」实际是加州 500-600、佛蒙特 283-467
- **把预测写成事实**：Gartner「2027 年底前 40% 项目被取消」是 2025-06 发布的**预测**

### 核查员也会误判，必须自己复核

出现「查不到/有反证」时，先确认它搜对了地方：

- Mem0 的 issue #4573 被误判为不存在——核查员搜的是 `anthropics/claude-code`，实际在 `mem0ai/mem0`
- ChatGPT 项目记忆 2025-08 被误判——`project-only memory` 与 `Projects` 功能是两回事
- Claude Cowork 记忆合并 2026-08-25 被误判——Cowork 产品 2026-01 发布，但记忆合并是 8 月

**可硬核实的数字自己动手取**：GitHub star 用 `curl https://api.github.com/repos/{owner}/{repo}` 取 `stargazers_count`，比搜来的区间值准。

## 二、逻辑关

- **每个单边结论旁配反方证据**。只写一方，文章就只剩卖方叙事
- **结构前后一致**：结论前置的体例要贯穿全篇；短清单里的数字必须与正文同值
- **区分「预测」与「已发生」**、「厂商自报」与「第三方复测」、「相关」与「因果」
- **核心论断先找反证**：提出一个判断时，先搜「反对这个判断的证据」。曾因此把「harness 不重要」改写成更站得住的版本——找到了「只改 harness 不动模型就让准确率涨 13.7 个百分点」的硬反证

## 三、文字关（去 AI 味）

分两件事做，顺序不能反：**先立保真边界，再动词**。

| 场景 | 用哪个技能 | 做什么 |
|---|---|---|
| 中文长文 / 公众号改稿 | `humanizer-zh` + `qu-aiwei-zh` | 先立边界，再扫描定位（默认组合） |
| 只要分数和命中清单 | `qu-aiwei-zh` | 跑脚本，不改稿 |
| 随笔要「加声音」 | `qu-aiwei-zh` + `references/pan-style.md` | 用表达方式加，不编故事 |
| 英文文本 | `humanizer` | `humanizer-zh` 只针对中文 |
| 清单 / 词表 / 说明书 | 都不用 E 类姿态分 | 这类文体靠列举反例，检测器会把反例当真命中 |

### 第一步：保真边界（`humanizer-zh`）

`qu-aiwei-zh` 管「像不像人写的」，`humanizer-zh` 管「改完意思有没有变」。31 条检查点每条都带「保留」边界，**是检查线索不是词语黑名单**——命中不等于要改，回上下文判断是否空泛、重复、歧义或与文体不符。

动词前先钉住这些：

- 不新增原文没有的事实、数字、人名、日期、来源、经历、实现细节
- 不丢失否定、比较对象、范围、条件、时间、完成状态、归因
- 「可能」不改成「确定」，「计划」不改成「已经完成」，「相关」不改成「因果」
- 三项列表 / 四字格 / 破折号 / 被动句按作用判断，不确定作用就保留

### ⚠️ 分数不够时不许补事实

`qu-aiwei-zh` 的结构维度会因「全文无数字」扣 12 分、「全文无第一人称」扣 8 分。**这两条是诊断，不是待办**：

- 原文确实没有数字 → 分数就停在那儿，**不许为了拿分编一个数**
- 原文是不需要第一人称的客观报道 → **不许硬塞「我」**

抬分只有三条路：删套话、改表达、调节奏。补数字只有两条路：一手来源已在手，或用户提供。够不着就不补。

### 第二步：扫描定位（`qu-aiwei-zh`）

目标：`qu-aiwei-zh` 扫描 **≥ 85 分**。

```bash
python3 ~/.workbuddy/skills/qu-aiwei-zh/scripts/scan_ai_flavor.py <稿>.md
```

### 删套话

值得注意 / 值得记录 / 值得单独强调 / 本质上 / 事实上 / 意味着 / 由此可见 / 不难看出 / 换句话说 / 换言之 / 殊途同归 / 显而易见 / 众所周知 / 更进一步说

改成直述。例：「最值得个人记住的其实是复盘里的一个细节」→「对个人最有参考价值的其实是复盘里的一个细节」→ 更好的是直接说细节是什么。

### 删黑话

护城河、生态位、闭环、打法、颗粒度、赋能、沉淀、赛道、倒逼、组合拳、卡位、底层逻辑

换法：护城河→优势；闭环→这一轮/整条链；打法→做法；赛道→方向；沉淀→积累/形成。

**不要误伤专业用法**：「口径」（官方口径/社区口径）、「对齐」（alignment）、「收敛」（数学语义）都是正常的。

### 降调段末金句

`**能搬走的数据，才是真正属于你的数据。**` → `能搬走的数据，才是真正属于你的数据。`

删完套话却满篇加粗金句，等于从「AI 体」变成「新闻通稿」——同样没人味。

### 保留的东西

- **「不是 A 而是 B」多数要保留**：「你要的是同事，不是神」「沙箱不是边界，是概率」都是有信息量的反转，只删纯修辞的重复
- **三段排比若内容扎实可留**，硬凑的才砍到两项或四项

### 扫描器的两个误报（别照着改坏）

`qu-aiwei-zh` 会把两类东西误判成 AI 味，改之前先自己看一遍原文：

- **「排比三段式」误报数据陈述**：`从 15 个精简到 2 个，准确率从 80% 升到…`、`从发布、被审计、更正到上线` 是时间/数据变化，不是修辞排比，**保留**。
- **「复盘」误报专有名词**：「37signals 退出云复盘」里的「复盘」是标题/专名，不改；只有「我们来复盘一下」这种动词套话才改。

判断优先级：**先看语义是不是真排比/真套话，再决定删不删**，不要按扫描器命中的字面动手。

### 加人味（只加表达，不加事实）

有「我」、有具体场景、有具体数字与人名、有不确定性表达（「其实」「不过」「还在想」）、句子长短交替、有真实细节而不是「很多人」「大多数」。

⚠️ 这一段说的是**表达方式**。原文没有第一人称、没有数字时，不许靠这一条去补——那正好踩中 `humanizer-zh` 的优先级第 1 条。加声音的手段是句长节奏、设问、括号自注（见 `pan-style.md`），配合删掉元叙述和教学腔。`humanizer-zh` 里写着同一句话：「用户要求增强个人风格时，用表达方式实现，不编故事。」

英文文本才走 `humanizer`：它的取向是 **Add soul**（主动注入个性），与中文改稿的**保真优先**方向相反，别把它的思路套到中文稿上。

### 工具纪律

**并行编辑同一文件会互相覆盖**——同一文件的多处修改必须走**单个串行脚本**，改完立刻复核关键字段是否落盘（曾丢过 8 处，含 star 数与日期两处关键修正）。

## 四、改稿红线

不改技术事实、数据、评测结论、代码块内容。改稿改的是阅读节奏与表达，不是重写。

外部工具改过的稿子（用户先拿别的模型改过一版再交回来）：**先核数字，再动文字，顺序不能反**。实测一轮揪出 7 处错值，其中 5 处是「比值对但绝对值错」——比值正确会让错误绝对值显得可信。判据：出现比值对而绝对值错，说明写的人是从别的口径倒推，该段所有数字都要重核。
